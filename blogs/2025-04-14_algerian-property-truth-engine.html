Building a Truth Engine for the
Algerian Property Market

Author
Farah (9otna)

Algeria's property market is one of the most opaque in North Africa. Listings are scattered across a dozen platforms, written in a mix of Darija, French, and MSA, with prices quoted in a currency that officially doesn't exist at the rate everyone uses. This is the problem DZ-PROP-TRUTH was built to solve.

The data exists. It just refuses to cooperate.

The core challenge

When we first started scraping listings, the raw data was genuinely difficult to work with — not because it was sparse, but because each platform had invented its own ontology. One called a studio a F1, another a T1, another 1p, and several just wrote "studio" in Arabic. Prices appeared in DZD, EUR, and an informal USD-parallel rate simultaneously.

There was no shared coordinate system, no standard wilaya code, and no canonical neighborhood vocabulary. Every field required its own normalization logic before it could be used in any downstream analysis.

Normalization pipeline

Our NLP normalization pipeline handles this in three stages. First, a language detector tags each field with its dominant script. Then a token-level normalizer maps known synonyms to a canonical schema. Finally, a confidence scorer surfaces records that need human review. 

def normalize_type(raw: str) -> tuple[str, float]:
    """Map informal listing type strings to canonical schema."""
    tokens = tokenize_darija_fr(raw.strip().lower())
    for token in tokens:
        if match := TYPE_SYNONYMS.get(token):
            return match, 1.0
    return fuzzy_match(tokens, TYPE_SYNONYMS)
⚠ Edge case

Listings in pied-de-page often contain the property type buried in a sentence. The token-level approach fails here — we fall back to a small fine-tuned classifier trained on 2,400 manually labelled examples.

Geospatial enrichment

The second major challenge was location. Most listings include a neighborhood name, but Algerian neighborhoods have no official geocoding standard. Our solution was to build a custom gazetteer from OpenStreetMap relations, supplemented with crowd-validated corrections, covering all 48 wilayas.

We run the full enrichment pipeline nightly via GitHub Actions, processing around 40,000 listings in under 12 minutes on standard compute. The output lands in BigQuery, partitioned by wilaya and clustered by property type, so regional queries stay cheap.

Results so far

After standardization, we achieved a 99%+ improvement in data retrieval efficiency through optimized API rate limiting, error handling, and TimescaleDB aggregation. Dashboard query times dropped from several minutes to under one second. The normalized dataset now covers approximately 400,000 listings with confidence scores attached to every field.

  • 48 wilayas fully geocoded and indexed
  • 12 property-type synonyms collapsed to a single canonical schema
  • 3 currency variants normalized to a single reference price
  • Nightly pipeline runs in <12 min via GitHub Actions

What's next

Phase two focuses on price modelling. We're building hedonic regression models per wilaya, using the normalized dataset as training data. Early results suggest we can estimate fair market value within ±8% for well-represented neighborhoods. The long tail — rural areas, rare typologies — is harder.

  • Deploy per-wilaya price indices with confidence intervals
  • Build a public Streamlit dashboard for journalists and researchers
  • Open-source the normalization lexicon under CC-BY
